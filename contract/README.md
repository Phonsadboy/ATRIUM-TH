# ATRIUM Contract

This folder stores generated API contract artifacts shared by the headless
system and the UI.

```bash
cd system
uv run python -m app.export_openapi ../contract/openapi.json
```

The source of truth remains the FastAPI app and Pydantic models under
`system/app`. Regenerate this schema after changing REST routes, request
models, or response models.

The generated schema includes the core company snapshot plus durable extension
records: artifacts, artifact versions, decisions, notifications, bulletins,
handoff messages, projects, war rooms, skills, preferences, triggers,
meetings, playbooks, lessons, evidence packs, critique reports, file imports,
knowledge-debt reports, logged department peeks, artifact content
read/write/diff/rollback surfaces, workspace git audit responses, and
company-wide budget/cost telemetry surfaces. Engine ticks also expose
trigger job counts so UI and tests can verify scheduler automation.
Executive bootstrap is exposed at `/api/executive`, derived from the seeded
executive department so clients can read provider/model/thinking/system prompt
and daily budget without reverse-parsing the company snapshot. Owner Profile is
exposed as a company-global aggregate at `/api/owner-profile`; clients can
upsert through `/api/owner-profile/preferences` and edit/delete individual
preferences through `/api/preferences/{preference_id}`.
Task records include hierarchy and completion metadata (`watchers`,
`parentTaskId`, `subTaskIds`, `deadlineAt`, `result`, `deliverables`) so the UI
can render real decomposition and audit completed work without reverse-parsing
activity text.
Project records include project-scoped shared context (`brief`, `sharedNotes`)
plus the final review state: a final artifact can sit in `in_review` with a
compatibility `resolve_project` audit record, and
`POST /api/projects/{projectId}/resolve` records the project resolution path
without making user approval a system-wide execution gate.
Deliverable preview is a dedicated contract surface: artifact versions can carry
preview metadata, and `GET /api/artifacts/{artifactId}/preview?version=...`
returns the preview descriptor plus inline text for readable markdown/diff/table
previews.
Artifact quality review is contract-backed: `POST
/api/artifacts/{artifactId}/review-gate` returns an `ArtifactQualityReview`
with the artifact, evidence pack, critique report, and persisted gate metadata;
`GET /api/critique-reports?targetType=artifact&targetId=...` retrieves durable
red-team reports without relying on transient UI state.
Destructive delete routes return guarded action responses that carry
checkpoint/audit metadata. In the owner-operated Full Auto profile, legacy
approval-shaped records are compatibility/audit records rather than blocking
execution gates.
Chat usage metadata includes RAG hit IDs and whether context compaction was
queued, so UI/runtime checks can distinguish memory-backed answers from plain
chat turns. Agentic chat tool calls are returned as `toolRuns` on both the
message and usage payload; these runs are also persisted as `agent_tool_run`
entities so clients can render durable tool-call cards without scraping text.
Chat replies stream through the existing WebSocket pulse channel using
message-scoped events (`msg_start`, `msg_delta`, `thinking_delta`, `msg_done`)
while `/api/messages/{threadId}/stop` cancels an active or queued generation.
Conversation management is contract-backed: regular chat sends, retries,
regenerates, edits, and war-room jobs can carry optional per-turn
`thinkingEffort` without mutating the department default. `/api/messages/{threadId}/regenerate`
creates a new assistant variant, `/api/messages/{threadId}/{messageId}/edit`
resends an edited user message on a branch thread, message action routes persist
pins/reactions, promotion routes write pinned chat content into department
knowledge with message provenance, and thread search/export/stats routes support
jump-to-message, markdown/json export, and scroll/new-count UI.
ATRIUM-specific chat metadata is contract-backed: war-room and meeting records
expose stable shared thread ids (`war:{warRoomId}` and `meet:{meetingId}`),
assistant/system messages can carry `participant`, `flow`, `warRoomId`,
`meetingId`, and `threadCost`, and the collaboration endpoints return the
scope record, participants, prompt context, flow, and recent transcript:
`/api/war-rooms/{warRoomId}/collaboration` and
`/api/meetings/{meetingId}/collaboration`. `/api/threads/{threadId}/cost`
returns the durable per-thread cost meter.
Reconnect replay is part of the contract: `/api/activity` returns durable
activity events after a timestamp or event id, and
`/api/threads/{threadId}/messages` returns durable chat messages after a
timestamp. Transcript archive entries generated by compaction expose
`threadId`, `messageCount`, and `transcript` for audit.
Memory provenance is first-class in the wire contract: knowledge entries expose
`source`, and department memory stats expose `workingSummary`,
`workingArchiveId`, `workingThreadId`, `workingMessageCount`, and
`workingUpdatedAt` so clients can audit which compacted archive is being used
as active working memory.
`/api/knowledge-debt` uses the same provenance-aware scoring rule: knowledge is
treated as sourced when it has an explicit `source` value or an auditable
provenance tag, and the report also counts stale, duplicate, and orphaned graph
signals for the knowledge-debt dashboard.
Notifications expose delivery controls through
`/api/notification-preferences`: clients can read defaults and patch per-event
delivery modes (`off`, `inbox`, `push`) plus quiet-hours settings without
changing existing notification CRUD/read routes.
Finance follows the current budget-telemetry design: department records no longer expose
`dailyBudgetUsd`, create/edit department inputs no longer accept per-department
budget caps, and `/api/budget` exposes only the company-wide forecast threshold
plus today's spend. The legacy `/api/departments/{dept_id}/budget` route is hidden
from OpenAPI and returns HTTP 410 for migration safety. Spend analytics are
available through `/api/cost-report` with scopes `day`, `month`, `project`,
`dept`, and `agent`.
Tool execution is also contract-backed: `/api/tools/run` returns a durable
`ToolRun` record and immediate execution while the company is running in
Full Auto. Risk metadata controls checkpoints, audit, rollback, and redaction,
not a blocking approval gate. `/api/policy` exposes the current Owner Mode
setting and tool catalog; legacy mode spellings such as `approve_all` are
accepted for compatibility and normalized back to `full_auto`.
Owner Mode compatibility endpoint aliases are also contract-backed at `/api/permissions/mode`,
`/api/tools/catalog`, `/api/tools/approvals`, `/api/tools/kill-switch`, and
`/api/tools/resume`. `/api/tools/runs` lists the audit trail, individual runs
can be read or cancelled through `/api/tools/runs/{runId}` and
`/api/tools/runs/{runId}/cancel`. `/api/audit/logs` and `/api/logs` expose a
read-only combined activity/legacy-approval/tool/note log, while `/api/audit/notes`
and `/api/logs/{logId}/notes` add append-only observations without mutating
existing audit records. Public tool-run responses redact secret-bearing input
fields in `args`, set `argsRedacted`, and list exact `redactedFields`; the
stored raw run remains available internally for execution/audit but is not
returned through tool-run detail/list or generic `tool_run` entity reads.
Generic entity `PUT`/`DELETE` is blocked for append-only/audited records such as
tool runs, checkpoints, audit notes, handoff messages, decision events, and
artifact versions so the generic entity surface cannot bypass the log model.
Provider metadata separates OpenAI Platform, ChatGPT account OAuth, Claude Code,
and direct Claude AI routes. Direct Anthropic uses `ATRIUM_ANTHROPIC_BASE_URL`
only when explicitly overridden.
